# mc-blender-bridge 协议规范 v1

> 本文档是 Python 参考实现（`blender_addon/mc_bridge/core/codec.py` 与
> `server_sim/`）、Java 实现（`mcmod/`）以及 Blender 插件三方共同遵守的契约。
> 一致性夹具（`tests/fixtures/`）由 Python 生成，Java 测试逐字节对拍通过。
>
> **存档模式**不使用 HTTP：`core/anvil.py` 的 `SaveClient` 直接解析存档文件，
> 但实现了与 `ApiClient` 相同的 Python 侧接口（chunk/mesh/versions/...），
> 且 chunk 返回与 MCC1 解码结果同构的 payload（`{dim,cx,cz,yBottom,sections}`），
> 因此下游网格器/调度器零改动复用。

## 通用约定

- 传输：HTTP/1.1，仅绑定 `127.0.0.1`（安全边界）。
- 多字节整数一律**小端**。
- 二进制响应默认 **zlib 压缩**，响应头 `X-MCB-Encoding: 2`；
  `none` 表示未压缩（贴图 PNG 固定 none）。
- 压缩协商：`/api/ping` 返回 `encodings: [2]`；客户端按响应头解压。
- 错误：JSON `{"error": "..."}`，HTTP 500/404/429（429 = 快照队列满，客户端退避重试）。

## 端点

| 端点 | 方法 | 参数 | 返回 |
|---|---|---|---|
| `/api/ping` | GET | – | JSON 能力协商 |
| `/api/blocks` | GET | – | JSON 方块分类表 |
| `/api/chunk` | GET | dim,cx,cz,ymin,ymax | MCC1 |
| `/api/mesh` | GET | dim,cx,cz,ymin,ymax,lod,ao,leaves | MCM1 |
| `/api/entities` | GET | dim,cx,cz,ymin,ymax | JSON 实体列表 |
| `/api/versions` | GET | dim,cx0,cz0,cx1,cz1 | 版本表 |
| `/api/texture` | GET | block,face | PNG 16×16 |

### /api/ping（JSON）

```json
{"mod":"mcbridge","modVersion":"1.0.0","mcVersion":"1.20.1",
 "encodings":[2],"modes":["raw","mesh"],"entities":true,
 "dims":[{"id":"minecraft:overworld","minY":-64,"height":384}],
 "maxQuads":200000}
```

`entities: true` 声明支持 `/api/entities`（R5）；旧版模组未声明该字段，
插件据此在控制模式下不请求实体（避免 404）。存档模式的数据源天然支持实体。

### /api/entities（JSON）

```json
{"entities":[
  {"id":"minecraft:painting","Pos":[8.5,70.0,8.0],"facing":0,"variant":"minecraft:kebab"},
  {"id":"minecraft:armor_stand","Pos":[4.5,72.0,4.5],"Rotation":[0.0,0.0],
   "Small":false,"ShowArms":true,"NoBasePlate":false,"Marker":false,"Invisible":false,
   "Pose":{"Head":[0.0,0.0,0.0],"Body":[0.0,0.0,0.0],"LeftArm":[90.0,0.0,0.0],
           "RightArm":[-90.0,0.0,0.0],"LeftLeg":[0.0,0.0,0.0],"RightLeg":[0.0,0.0,0.0]}}
]}
```

按区块返回实体列表（R5 只提取插件需要的两种：画 / 盔甲架，其它类型暂不下发）：

- 画：`id` / `Pos`（脚底/底边中点）/ `facing`（0=南 1=西 2=北 3=东）/ `variant`；
- 盔甲架：`Pos` / `Rotation`（[yaw, pitch]，度）/ `Small` / `ShowArms` /
  `NoBasePlate` / `Marker` / `Invisible` / `Pose`（各部件 [pitch, yaw, roll] 度）。
  插件侧在**运行时**按 Pose 装配分层实体模型（MCBA v5 实体模型段），
  详见 `docs/设计方案.md` §5.9 与 `core/entities.py`。

### /api/blocks（JSON）

```json
{"blocks":{"minecraft:stone":{"class":1,"tint":null,"color":[0.55,0.55,0.55]},
           "minecraft:oak_leaves":{"class":4,"tint":[0.35,0.55,0.25],"color":[0.35,0.45,0.2]}},
 "nBlocks":1050}
```

方块 class（六类）：

| class | 名称 | 语义 | 剔除行为 |
|---|---|---|---|
| 0 | AIR | 空气 | 不发射面 |
| 1 | OPAQUE | 实心不透明 | 遮挡一切；相邻面剔除 |
| 2 | TRANSPARENT | 玻璃/冰 | 同类同方块相邻面剔除 |
| 3 | LIQUID | 水/岩浆 | 同类相邻面剔除 |
| 4 | CUTOUT | 树叶/花草 | 不遮挡任何面 |
| 5 | NONCUBE | 楼梯/台阶等 | 视觉不遮挡（完整方块近似） |

### /api/mesh 参数

- `lod`: 0=完整网格（默认 AO 开）；1=完整网格 AO 关；2=高度壳网格（AO 恒关）
- `ao`: `0`/`1` 覆盖 lod 默认值
- `leaves`: `fancy`（默认，树叶不遮挡）/ `fast`（树叶按实心处理）

## 二进制格式

### MCC1（原始区块）

```
"MCC1"            u8[4]
version           u8 = 1
dim               u16 长度 + UTF-8
cx, cz            i32, i32
yBottom           i16          # 本载荷最低 Section 的世界 y
secCount          u8           # 本载荷 Section 总数（含空）
present           u32          # bit i = 第 i 个 Section 非空（LSB first）
存在 Section 依序:
  palSize         u16
  调色板 × palSize:
    class         u8
    name          u16 长度 + UTF-8（"minecraft:stone[facing=north,...]"）
  bits            u8           # palSize==1 时为 0，否则 max(4, bit_length(palSize-1))
  indices         ceil(4096*bits/8) 字节
```

- 索引顺序：`cellIdx = (y<<8) | (z<<4) | x`（Section 内本地坐标）。
- 位流：逐 cell 逐 bit、LSB-first 连续排列
  （等价 `numpy.packbits(bits, bitorder='little')`）。

### MCM1（服务端成品网格）

```
"MCM1"            u8[4]
version           u8 = 1 | 2
dim, cx, cz, yBottom      同 MCC1
palSize           u16
调色板 × palSize:  class u8 + name
flags             u8           # bit0 = 含 AO
quadCount         u32
每 quad:
  verts           12 × i16     # 4 顶点 ×(x,y,z)，区块局部坐标，外向 CCW
  dir             u8           # 0..5 = +X,-X,+Y,-Y,+Z,-Z
  block           u16          # 区块级调色板下标
  ao              4 × u8       # 顶点对齐（flags.bit0=1 时存在）
--- 以下仅 v2（群系染色，R8）---
biomeNameCount    u16
群系名 × n:        name         # 下标即"群系 id"；0 保留给"未知"，空串
biomeId           quadCount × u8   # **每面**一个群系名表下标
```

- 顶点坐标范围：x,z ∈ [0,16]，y ∈ [0, ymax−yBottom]。
- v1 中 tint 不上线：由客户端按 `/api/blocks` 的 tint × AO 曲线计算顶点色
  （顶点色 = tint × shade(ao)，shade = [0.45,0.65,0.85,1.0]）。
  加载资产包后，改为按资产包声明的**逐面 tint 掩码**染色（见下）。
- **v2（R8）**：服务端额外下发**逐面群系 id**。前提是服务端的贪心合并键**包含
  群系** —— 否则一个合并矩形可能横跨群系边界，而每面只有一个 id，边界处会串色。
  客户端把 id 经资产包的群系色表（`AssetPack.biome_tint`）换算成染色：
  与存档模式完全同构（同一份 `_quad_cells` 反推格子归属）。
  面记录仍是定长，v1 前缀不变，因此旧客户端能照常解析 v1 报文；
  面板上的「按群系调色」开关关闭时，客户端**不使用** v2 段（退回常量色）。
  群系名用空串表示"未知"，客户端对空名不做染色（退回常量色）。

### MCBA1（本地资产包，非 HTTP）

由 `tools/bake_assets.py` 从客户端 jar / 资源包烘焙，供插件本地加载
（控制/存档模式通用）。小端：

```
"MCBA1"           u8[5]
version           u8 = 5（读取端同时兼容 1/2/3/4）
mcVersion         str
--- 贴图 ---
texCount          u32
× texCount:  name str | w u16 | h u16 | len u32 | RGBA 字节（首帧，16×16 起）
--- 烘焙变体 ---
varCount          u32
× varCount:  quadCount u16
  每 quad:  verts 12×i16（v2 起为 1/256 方块单位；v1 为 1/16；读取端统一换算为
                       1/16 内部单位，含 blockstate 旋转）
            dir u8 | tex u16 | tint i8 | cull u8 | uv 4×f32（0..16 像素坐标）
  变体级信息（v3 起）: class u8 | tintMask u8 | useModel u8
            | top u16 | side u16 | bottom u16（0xFFFF = 该面无烘焙贴图）
--- 方块状态 ---
blockCount        u32
× blockCount:  name str | mode u8（0=variants 1=multipart）| ruleCount u16
  每 rule:  pairCount u8；(key str, value str)×pairCount | variant u16
            （value 以 `|` 分隔多值；variants 模式取最具体子集匹配，
              multipart 模式取全部匹配）
--- 方块信息 ---
infoCount         u32
× infoCount:  name str | class u8 | tintMask u8 | useModel u8
              | top u16 | side u16 | bottom u16
              （tintMask bit0=top bit1=bottom bit2=side；
                useModel=1 表示应注入烘焙模型几何而非整方块近似）
--- 画变体（v4 起，1.21+ painting_variant） ---
paintingCount     u32
× paintingCount: name str | w u16 | h u16 | tex u16（0xFFFF = 无贴图）
              （w/h 为画面尺寸（方块数）；tex 指向贴图表里的画面贴图）
--- 实体模型（v5 起，运行时装配的分层实体模型） ---
entityModelCount  u32
× entityModelCount: name str | jsonLen u32 | JSON UTF-8
              JSON = {"texW","texH","tex":"<贴图名>","parts":[分层部件树]}；
              顶点为部件**局部坐标**（1/16 方块单位，以该部件 pivot 为原点，
              未应用任何变换），运行时按实体 Pose 装配（见 core/entities.py）
--- 群系染色表（v6 起，R8） ---
biomeCount        u32
× biomeCount: name str | grass u32 | foliage u32 | water u32
              （均 0xRRGGBB。由 tools/bake_assets.py 从客户端 jar 的
                data/minecraft/worldgen/biome/*.json +
                textures/colormap/{grass,foliage}.png 算出；取值公式与 modifier
                常量对齐原版 Biome / GrassColors / FoliageColors 的字节码）
```

- **状态粒度（v3）**：变体级信息随 `blockstate` 规则解析，因此同一方块的不同
  状态各拿自己的值——`oak_slab[type=double]` 是 OPAQUE/不注入模型，
  `[type=bottom]` 是 NONCUBE/注入半砖模型；`grass_block[snowy=true]` 用雪顶贴图。
  解析路径：状态名 → `变体级信息`；规则未命中（如只给基础名）→ 退回 `方块信息`。
  v1/v2 包没有变体级信息，读取端一律走方块级（行为与旧版一致）。
- class 由模型形状（非整立方 → NONCUBE）与贴图 alpha 推断，供存档模式兜底分类；
  共享分类表（`core/blocks.py`）优先。可用 `tools/bake_assets.py --classes`
  （`mcbridge-classes.json`）手工覆盖 class / use_model / 贴图，未生效的条目在
  烘焙结束时告警。
- **画变体（v4）**：1.21 起画变体由数据驱动
  （`data/<ns>/painting_variant/<id>.json` 的 `width`/`height`/`asset_id`），
  `tools/bake_assets.py` 连同贴图（`textures/painting/`）一起烘进 v4 资产包。
  运行时按存档实体的 `variant`/`facing`/`Pos` 现场生成平面四边形
  （`core/entities.py`；定位约定与未对拍项见 `docs/roadmap.md` R5）。
  注意画贴图是 16×宽 × 16×高 的竖条（1×2 的画就是 16×32），**不能**套用
  "高度是宽度整数倍即动画条带"的裁剪启发式，否则会丢掉下半幅 —— 烘焙器对
  画贴图显式关闭该启发式（`_ensure_texture(..., strip=False)`）。
- **实体模型（v5）**：盔甲架等原版形状是代码定义模型（非 JSON），由
  `tools/be_models/DumpEntityModels.java` 从客户端 jar 的模型工厂导出为**分层**
  模型（每部件 pivot / 默认旋转 / 本地顶点），随资产包下发；插件在运行时按
  实体 NBT 的 Pose 装配（变换链与 ModelPart 一致：T(pivot)·Rz·Ry·Rx，Pose 覆盖
  默认旋转；部件显隐与全局变换对照 `ArmorStandEntityModel.setAngles` 与
  `setupTransforms` 反汇编，见 `core/entities.py`）。换 MC 版本后需重跑
  `tools/dump_be_models.ps1`。
- **群系染色（v6）**：草/叶/水的染色按**该格所在群系**取色。烘焙期从客户端 jar 的
  `data/minecraft/worldgen/biome/*.json` 与 `textures/colormap/{grass,foliage}.png`
  算出每个群系的三通道 RGB 写进 v6 段；取值公式与 modifier 常量（`SWAMP`、
  `DARK_FOREST`、`MathHelper.clamp`）对齐原版字节码，插件侧不做算法复刻。
  存档模式由 `anvil._decode_biomes` 读 section 的 4×4×4 调色板（bits 下限 1，
  且兼容"只有 palette 没有 data"的单值形态；索引序 `(y, z, x)` 与方块一致）；
  网格侧群系维度进入贪心合并键，**只对声明染色的方块生效**，顶点色按
  "面所属格子"取色。换 MC 版本后需重烘资产包。
- 模型几何由 mesher 在 `useModel=1` 的格子上注入（顶点 1/16 单位，
  缩放后与完整方块面同坐标系）；`cullface` 对相邻不透明方块生效。
- **顶点精度（v2）**：v1 按 1/16 方块取整，模组模型（Blockbench）常见的
  0.25/0.5 像素坐标与零厚度面会被压成零面积面而整片消失；v2 以 1/256 方块
  （= 1/16 像素）存储，亚像素几何得以保留（读取端 v1/v2 均兼容）。
- **blockstate 旋转次序**：`x` 先于 `y`（等价 MC 的 R_y∘R_x，已用 MC 本体
  `ModelRotation.get(x,y)` 逐组核对 16 种组合）。注意 MC 的 `getDirectionTransformation()`
  给出的是另一套（转置）映射，仅供 uvlock 使用，**不能**用来校验顶点朝向。
- `uvlock`：已实现。按 MC `BakedQuadFactory.uvLock` 变换 UV 矩形**并改写面的
  rotation 索引**（索引决定角点↔矩形角的对应，漏掉它会让 90°/270° 下的贴图转 90°），
  矩阵公式 `M = T(0.5) · D(d) · R⁻¹ · D(d')ᵀ · T(-0.5)`（D =
  `AffineTransformations.DIRECTION_ROTATIONS`，R = x/y 旋转，d' = R·d，
  `T(±0.5)` 为绕方块中心的平移），已用 MC 本体 96 组 (x,y,面) 矩阵、
  288 组 (x,y,面,矩形) 的「矩形 + 新 rotation + 每角点 UV」逐条核对。
  典型效果：倒置楼梯（x=180）顶/底面 UV 不变、四个侧面 UV 转 180°，
  即贴图不再随模型翻转而倒过来；y=90/270 的楼梯与栅栏各连接面贴图朝向正确。
- 流体几何不在资产包里（形状取决于邻居），由网格器按 MC `FluidRenderer`
  现场生成：见《设计方案》§5.7 流体几何与 `core/mesher.py::_fluid_quads`。
- 无 JSON 几何的方块实体（箱子/床/告示牌/旗帜/潜影盒/头颅/装饰陶罐/传送门框架/
  钟等）使用**原版模型**：`tools/dump_be_models.ps1` 从客户端 jar 调用原版
  `TexturedModelData` 工厂，导出烘焙后的顶点/UV/面法线到
  `tools/vanilla_be_models.json`；烘焙期再按原版渲染器的矩阵变换（facing /
  rotation / attachment 等）与贴图规则（`textures/entity/**`）生成变体。
  未收录的方块退回简化代理模型（简化盒 + 粒子贴图兜底立方体）。
- UV 归一化：Java 模型 UV 恒以 0..16 为单位（`texture_size` 按 `texture_size/16`
  缩放后归一化会抵消），除以 16 并翻转 v 轴到 Blender 约定（v 自底向上）。
- 方块状态属性随 palette 名字传递（如 `minecraft:oak_stairs[facing=east,...]`），
  无需改动 MCC1/MCM1 线格式。

### 版本表（/api/versions）

```
count             u32
× count: cx i32, cz i32, version u64
```

版本号在区块内任何 `setBlockState` 时 +1（mixin 拦截）。客户端低频轮询，
命中变化即重新入队对应区块。

## 面生成规则（与实现一致性绑定）

1. 可见性（a 为面所属方块，b 为相邻方块）：
   a=air → 不可见；b=OPAQUE → 不可见；a=OPAQUE → 可见；
   a,b 均 TRANSPARENT 且同 id → 不可见；a,b 均 LIQUID → 不可见；其余 → 可见。
2. 贪心合并约束 = (方向, 方块 id, AO 签名)；AO 遮挡集 = {OPAQUE, NONCUBE}。
3. UV 规则：±Y 面 (x,z)；+X/−X 面 (z,y)；+Z/−Z 面 (x,y)。块单位 UV，
   贴图 `Repeat` 平铺。
4. 输出面仅属于中心区块（拼装 3×3 邻域用于跨边界剔除与 AO）。
