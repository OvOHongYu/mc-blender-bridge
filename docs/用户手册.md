# MC Bridge 用户手册

> 面向动画/渲染使用者。协议与算法细节见《协议规范.md》《设计方案.md》，
> 未来规划见《roadmap.md》。

## 1. 你需要准备什么

按选择的**加载模式**而定：

| 组件                                    | 控制模式      | 存档模式 |
| ------------------------------------- | --------- | ---- |
| Minecraft Java 版 1.21.1 + Fabric      | 真实世界渲染时必需 | 不需要  |
| mcbridge 模组（`mcmod/build/libs/*.jar`） | 真实世界渲染时必需 | 不需要  |
| Minecraft **存档文件**（`region/*.mca`）    | 不需要       | 必需   |
| Blender 3.6+ / 4.x                    | 是         | 是    |
| mc\_bridge 插件（`blender_addon/`）       | 是         | 是    |

没有 Minecraft 也可以先用 `server_sim/mc_server_sim.py` 体验控制模式完整流程。

## 2. 安装

### 2.1 安装 Blender 插件

方式 A（打包安装，推荐使用发行包里的 `mc_bridge-<版本>-blender-addon.zip`）：

```bash
cd blender_addon && zip -r mc_bridge.zip mc_bridge/
```

Blender → 编辑 → 偏好设置 → 插件 → 安装 → 选择 zip → 勾选启用。

方式 B（开发模式）：把 `blender_addon/mc_bridge` 目录放入 Blender 的 addons 目录。

### 2.2 安装 MC 模组（仅控制模式需要）

```bash
cd mcmod && gradle build    # 需要 JDK 17+，首次会下载依赖
```

- **推荐**：独立服务端（`server.jar` + Fabric loader），无 GPU 占用，也没有
  单人游戏 ESC 暂停冻结集成服务端的问题。
- 单人模式也可以：启动世界后 **Esc 菜单 → 对局域网开放**（否则暂停时查询会卡住）。
- 把 jar 放入 `mods/`，启动后日志出现
  `MC Bridge API 已启动: http://127.0.0.1:8788` 即成功。

> 玩家不需要在取景点附近：模组会按坐标强制加载/生成查询的区块。

## 3. Blender 侧使用

打开 N 面板 → **MC Bridge** 分类。面板第一栏是**加载模式**：

### 3.1 加载模式

| 模式       | 用法                                       |
| -------- | ---------------------------------------- |
| **控制模式** | 填主机/端口 → 连接。数据来自运行中的 MC 实例或 `server_sim` |
| **存档模式** | 选择存档目录 → 连接。直接解析存档文件，无需 MC 运行            |

- 存档目录 = 世界文件夹（含 `region/` 与 `level.dat`）：
  - 单人：`.minecraft/saves/<世界名>/`
  - 服务端：`<服务端>/world/`
- 维度由 `dim` 属性控制：`minecraft:overworld` / `minecraft:the_nether` / `minecraft:the_end`。
- 存档模式为**只读快照**：游戏内改动不会反映（版本轮询自动跳过）；
  贴图为内置程序化生成。

### 3.2 连接与锚点

1. 选择模式、填好参数 → 点击 **连接**。状态栏显示已连接与版本信息。
2. **锚点对象**：默认跟随**场景相机**；也可以选一个空物体/角色作为加载中心。
3. 勾选 **播放时跟随帧**：播放动画时区块随相机逐帧装卸。

### 3.3 根空物体（场景组织）

连接后自动创建根空物体 **`MCB_Root`**（在「MC Bridge」集合中）：

- 所有区块对象以 `MCB_Root` 为父级，位置是根物体局部坐标；
- 勾选 **相机归入根节点**（默认开）时，连接会自动把场景相机挂到根节点下，
  保持世界位姿不变；
- **整体变换**：选中 `MCB_Root` 移动/旋转/缩放，全部区块与相机同步跟随；
- 加载判定用的是相机**相对根物体**的位置——移动根物体不会触发区块重新装卸；
- 卸载全部区块不会删除根空物体（保留场景结构）；
- 手动重新绑定：点 **绑定相机到根节点**。

### 3.4 加载策略（默认即可用）

| 参数                | 默认          | 说明                                                       |
| ----------------- | ----------- | -------------------------------------------------------- |
| 加载半径              | 8 区块（128 格） | 锚点周围圆形加载                                                 |
| 卸载半径              | 11 区块       | 迟滞带：防止镜头来回晃动反复装卸                                         |
| LOD1 距离 / LOD2 距离 | 6 / 10      | 远处分别关 AO / 换高度壳网格                                        |
| ymin / ymax       | -64 / 320   | 世界裁剪；动画只涉及地表时缩窄可省内存                                      |
| 模式                | mesh        | 服务端网格（连真实模组推荐）；raw=Blender 本地网格（连 server\_sim 时更快，多线程并行） |
| 并发数 / 每帧应用        | 8 / 8       | 拉取并发与主线程每 tick 应用上限（卡顿就调小）                               |

> 性能提示：连 `server_sim` 时切 **raw** 模式更快（网格化在 Blender 侧多线程并行，
> 而 sim 是 Python 单进程受 GIL 串行）；连真实 Java 模组时保持 **mesh**。

### 3.5 渲染与交付

- **预热渲染**：按预览帧范围采样相机位置，把需要的区块全部加载并**冻结卸载**，
  然后渲染。播放/渲染期间不会因缺区块而等待。
- **烘焙静态化**：把当前已加载区块导出为 `.blend` 库文件（含网格与材质），
  渲染农场无需安装 MC 即可链接使用。
- **刷新**：手动重新拉取全部 LIVE 区块（控制模式一般不需要，版本轮询会自动处理）。
- **卸载全部**：删除所有区块对象与网格（保留 `MCB_Root`）。

### 3.6 材质与外观

- 每个方块 × 面组（top/side/bottom）一个材质：`MCB_<方块>__<面>`。
- 节点：`贴图(Repeat+Closest) × 顶点色(tint×AO) → Principled`。
- 水/玻璃/树叶自动设置混合模式；树叶快速模式（fast）会把树叶当实心，减面更多。
- 贴图缺失时先显示平均色占位，后台拉取完成后自动接入节点（控制模式）；
  存档模式直接使用内置程序化贴图。
- 控制模式服务端贴图：把 PNG 放到服务端工作目录
  `mcbridge/textures/<方块名>__<面>.png`（可从任意资源包
  `assets/minecraft/textures/block/` 提取），否则是程序化色块。

## 4. 推荐工作流（动画镜头）

1. Blender 里布置相机动画（手持抖动、推拉等）。
2. 点击 **预热渲染**（或手动播放一遍让缓存热起来）。
3. EEVEE 试渲染确认构图与材质。
4. 正式输出：本机渲染直接 F12/动画；渲染农场用 **烘焙静态化** 交付。

## 5. 常见问题

| 现象                  | 原因/处理                                             |
| ------------------- | ------------------------------------------------- |
| 连接失败（控制模式）          | 模组未装/服务未启动/端口不对；`curl 127.0.0.1:8788/api/ping` 排查 |
| 打开存档失败（存档模式）        | 目录选错：确认所选文件夹**直接包含** `region/` 与 `level.dat`      |
| 存档区块显示为异常大方块        | 旧版插件 bug（调色板解析），请更新到最新插件                          |
| 查询偶发 429（控制模式）      | 快照队列满：降低并发数（默认会自动退避重试）                            |
| 视口卡顿                | 减小「每帧应用」；缩小加载半径；LOD 距离调近                          |
| 树叶太密/太厚             | 切换 `leaves=fast`                                  |
| 楼梯/栅栏形状不对           | v1 以完整方块近似；敏感镜头用真方块替换或等后续版本模型烘焙                   |
| 游戏 ESC 后 Blender 卡住 | 单人模式请先「对局域网开放」，或改用独立服务端                           |
| 地图改了没更新（控制模式）       | 版本轮询在相机静止时每 5 秒一次；急用点「刷新」                         |
| 移动 MCB\_Root 时区块闪断  | 不应发生：加载判定用相对坐标；若复现请反馈                             |

## 6. 性能参考（真实 Blender 4.5 实测）

- R=4（49 区块）加载：控制模式热缓存 **\~0.2s**、raw \~1.5s、冷缓存 \~2.2s；
- 服务端网格化（Java 侧）：单区块毫秒级（Python 参考实现 \~41ms，Java 快一个量级）；
- 视口存活对象数 = 加载半径内区块数（默认约 200），每对象一个网格；
- 区块/网格双层 LRU 缓存：LOD 切换与相机回看几乎瞬时。
