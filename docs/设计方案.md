## 0. v1.1 架构新增

### 0.1 加载模式（数据源抽象）

插件把「区块数据从哪来」抽象为两个可切换的后端，共用同一调度器：

```
MCB_Properties.load_mode
  ├─ control  → core/net.py  ApiClient      （HTTP：Fabric 模组 / server_sim）
  └─ save     → core/anvil.py SaveClient    （直接解析 Anvil 存档，同构接口）
```

`SaveClient` 与 `ApiClient` 接口同构（chunk/mesh/versions/texture_png/ping/blocks），
调度器零改动复用。存档模式内部固定走 raw 路径（Blender 侧多线程网格化，
numpy 释放 GIL 真并行），版本轮询恒 0（静态快照不重载）。

**Anvil 解析要点**（`core/anvil.py`）：

- NBT 大端解析：TAG 结尾驱动，兼容 1.18+（sections 挂根）与旧版（`Level` 包裹）；
- Region `.mca`：文件头偏移表一次读取 + 按扇区惰性读取（不整文件驻留内存），
  句柄 LRU（64）；zlib/gzip/无压缩三种区块压缩；
- PalettedContainer 位压缩：**1.16+ 条目不跨 long**（每 long 存 `64//bits` 项，
  高位补零）与 1.15- 连续位流两种格式按 data 长度自动识别；
  bits 由 palette 大小精确推导 `max(4, bit_length(palSize-1))`；
- palette 元素兼容 compound（`{Name, Properties}`，真实存档）与字符串两种形式；
- 区块 payload LRU（512）——NBT 解析结果复用，避免重复解压；
- 未知方块按 base 名查共享分类表，兜底 class=1（不透明）。

### 0.2 根空物体场景组织

```
MCB_Root (Empty)
  ├── MCB_ow_0_0      位置 = 根局部坐标 (cx*16, -cz*16, yBottom)
  ├── MCB_ow_1_0
  └── Camera          连接时自动挂载（保持世界位姿）
```

- 区块 `obj.parent = MCB_Root`，位置存根局部坐标——整体变换带动全部区块与相机；
- **加载判定用相机相对根物体的位置**（`matrix_world.inverted()` 逆变换），
  根物体自身变换不触发装卸；
- 卸载/计数/烘焙逻辑保护根物体不被误删；
- 相机挂载在连接时自动执行（`auto_bind_camera` 可关），保持世界变换仅改父子关系。

### 0.3 性能设计（实测 R=4/49 区块，Blender 4.5）

| 手段 | 位置 | 说明 |
|---|---|---|
| keep-alive 长连接 | `net.py` | 每线程一条 `http.client` 连接，失效自动重建（原来每请求新建 TCP） |
| 邻域请求合并 | `scheduler.py` ChunkStore | 3×3 邻域 payload 在途去重：多线程同时网格化相邻区块只拉一次 |
| 服务端网格 LRU | `server_sim` | mesh 结果缓存（8192），setblock 时失效；LOD 切换/回看近瞬时 |
| 客户端网格 LRU | `anvil.py` SaveClient | 存档模式 mesh 产物缓存（2048） |
| 区块 payload LRU | 双后端 | 已解码区块复用，免重复解压 |
| MCM1 解码向量化 | `codec.py` | 逐 quad frombuffer → 整块 stride 切片（~4×） |
| 几何装配向量化 | `mesher.py` | tint 预取 + np.unique 组合键求材质槽（逐 quad 循环消除） |
| 主线程 foreach_set | `importer.py` | from_pydata+tolist → 全 foreach_set（快 5–10×） |
| 网格器等效微优化 | `mesher.py` | isin→布尔、y 轴顶部空层裁剪、非空 plane 预筛、AO uint8 算术 |

实测：mesh 模式热缓存 2.38s→**0.19s**（12.5×）；raw 模式 1.72s→**1.53s**。

## 1. 背景与目标

### 1.1 现有流程的痛点

传统流程「选区 → Mineways / jMC2Obj / Litematica 导出 → 一次性导入 Blender」本质上是**静态全量快照**：

| 痛点 | 根因 |
|---|---|
| 场景一大 Blender 就爆内存/卡死 | 面数 = 整个场景面数，与镜头实际看到的内容无关 |
| 无法按需增减 | 没有运行时的加载/卸载机制，内存无法平衡 |
| 地图改动需重新导出 | 数据链路是单向离线的 |
| 导出工具版本适配滞后 | 直接解析存档格式，MC 版本一升级就失效 |

### 1.2 方案目标

1. Blender **运行时**通过本地回环（localhost）与正在运行的 MC Java 版实例通信；
2. 以**相机位置为锚点**，在合适的时机动态加载/卸载区块（带迟滞，防止镜头来回抖动导致反复加载）；
3. 数据在进入 Blender 前/中完成**面剔除**与**贪心合并**，单区块减面 60–95%；
4. 为最终渲染提供**确定性**（预热/烘焙两条路径），支持无 MC 环境的渲染农场；
5. 不干扰游戏运行：模组只监听 127.0.0.1，玩家可以完全 AFK。

### 1.3 非目标（明确排除）

- 实体/方块实体（箱子内容、盔甲架等）的同步——可作为后续扩展；
- 跨机器网络部署（只考虑本机）；
- 游戏画面级实时同步——目标是给动画取景用的"几何影子"，不是联机画面流。

### 1.4 为什么必须借助运行中的实例（而不是继续解析存档）

1. **数据保真**：实例内拿到的 BlockState 已包含数据包、模组方块的真实状态与遮挡属性，不用自己跟随存档格式的版本演化；
2. **无文件并发问题**：直接读 region 文件会撞上游戏异步写入，需要 `save-all flush` 才能保证一致，而实例内查询天然一致；
3. **强制加载**：模组按坐标强制加载区块即可查询，玩家不在场也能取到远离出生点的动画取景区；
4. **一手周边数据**：群系染色、方块贴图、（客户端模式下）官方方块模型四边形，都能顺手拿到。

## 2. 总体架构

```
┌───────────────── Blender（Python 桥接插件）─────────────────┐
│  N面板控制 ── 调度器 ──► 优先级队列 ──► 工作线程池(HTTP拉取)    │
│      ▲                    │                      │          │
│  相机/帧回调(4Hz轮询)       │                   ready队列      │
│                         卸载判定              主线程 timers    │
│                 对象池/集合 · 材质缓存 · LRU · orphan清理  ◄──┘  │
└──────────────────────────┬──────────▲───────────────────────┘
        GET /chunk /mesh     │          │  MCC1 调色板数据 /
        /versions /texture   │          │  MCM1 成品网格 / PNG贴图
┌──────────────────────────▼──────────┴───────────────────────┐
│            本地 MC Java 实例（推荐独立服务端，127.0.0.1）        │
│  Fabric 服务端模组：                                          │
│   内嵌 HttpServer(JDK自带) → 请求入队(server线程做快照)         │
│   → 跳过空Section → 调色板+位压缩编码 → zstd                  │
│   →（可选）Java侧贪心网格器：剔除+合并+AO顶点色                 │
└──────────────────────────────────────────────────────────────┘
```

### 2.1 组件职责

| 组件 | 职责 |
|---|---|
| MC 模组·HTTP 服务 | 暴露区块/网格/贴图/版本查询 API；仅绑定 127.0.0.1 |
| MC 模组·快照器 | 在 server 线程安全读取区块 → 拷贝 Section 调色板 → 离线编码压缩 |
| MC 模组·贪心网格器（可选） | 面剔除 + 贪心合并 + AO，直接输出成品 quad 流 |
| Blender·调度器 | 相机锚点计算、加载/卸载半径、优先级、节流、重试 |
| Blender·导入器 | 主线程分帧创建/销毁 object，foreach_set 快速建 mesh |
| Blender·内存管理 | LRU 卸载、mesh 数据块删除、孤立数据定期清理、LOD 可见性 |

### 2.2 关键决策表

| 决策点 | 选择 | 理由 | 备选 |
|---|---|---|---|
| 数据源 | 运行中 MC 实例 + Fabric 模组 | 保真、无并发写问题、可强制加载 | 直接读存档（见 §9） |
| 运行形态 | 独立服务端 server.jar + 服务端模组 | 无 GPU/画面占用，且**不存在单人 ESC 暂停冻结服务端的问题** | 单人存档"对局域网开放" |
| 传输 | 内嵌 HTTP（JDK 自带 HttpServer），二进制 body + zstd | 零第三方依赖、curl 可调试、实现量小 | 自定义 TCP/WebSocket |
| 减面位置 | **默认 Java 侧成品网格**；Blender 侧网格器作备选 | Python 循环受 GIL 限制，Java 侧快一个数量级且天然拥有邻居数据 | 模式 A：传原始块数据，Blender 侧网格化（调试/风格化用） |
| 材质 | 每方块一个材质 + **块单位 UV + Repeat 平铺** | 贪心合并产生跨多格的大四边形，只有 Repeat 平铺能保证纹理正确；图集无法在子矩形内平铺 | 全图集 + 拆分四边形（放弃合并收益，不取） |
| 对象粒度 | 每区块列（16×384×16）一个 object | 对象数可控（R=10 时约 350 个），空 Section 不产生任何几何 | 每 Section 一个 object（数量爆炸，不取） |
| 区块版本 | mixin 拦截 `LevelChunk#setBlockState` 递增计数器 | 低成本感知游戏中改动，支撑增量刷新 | 每次全量哈希（贵） |

### 2.3 减面位置的模式对比

| | 模式 A：原始块数据，Blender 侧网格化 | 模式 B：Java 侧成品网格（默认） |
|---|---|---|
| 单区块传输量 | 3–30 KB（压缩后） | 30–120 KB（几何 quad 流） |
| Blender CPU 占用 | 高（Python 循环 + GIL） | 低（只做解码与导入） |
| 灵活性 | 完全自定义合并/风格化策略 | 受模组输出格式限制 |
| 邻居数据 | 需多拉一圈外圈区块用于跨界面剔除 | 模组直接查世界，无此问题 |
| 适用 | 开发调试、特殊风格化 | 生产默认 |

## 3. MC 侧：数据服务模组（Fabric）

### 3.1 运行形态

- **推荐**：官方 `server.jar` + Fabric Server Mod。无渲染开销，服务端永不暂停，动画制作时后台常驻即可。
- **替代**：单人存档选择"对局域网开放"。注意：单人游戏按 ESC 会**暂停集成服务端**，导致查询阻塞——开放局域网后不再暂停。
- 模组只监听 `127.0.0.1`，无鉴权压力（单机环境）；玩家无需位于取景区。

### 3.2 线程模型与安全

```
HTTP线程(JDK) ─► 请求入队(有界队列, 拒绝时返回429) ─► server线程:
                    按坐标取/强制加载 Chunk
                    将涉及 Section 的 PalettedContainer 拷贝为快照
                 ─► 工作线程: 编码(调色板+位压缩) + zstd ─► 响应
```

- 区块访问必须发生在 server 线程（`server.execute` 入队），快照拷贝之后即可离线处理，不阻塞游戏 tick；
- 快照开销约 5–20ms/区块，靠队列削峰：并发快照上限 2，队列容量 64；
- 空气 Section 直接跳过（1.18+ 世界 384 高 = 24 个 Section，地表区块通常只有 3–8 个非空）。

### 3.3 HTTP API

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/ping` | GET | 能力协商：模组版本、MC 版本、维度列表、世界高度范围、支持的编码（zstd/none）、支持的模式（raw/mesh） |
| `/api/blocks` | GET | 方块分类表：id → class 字节（§3.5），供 Blender 侧做剔除/材质决策 |
| `/api/chunk?dim=&x=&z=&ymin=&ymax=` | GET | 单区块二进制负载 MCC1（§3.4） |
| `/api/mesh?...`（v2/模式B） | GET | 单区块成品网格 MCM1（§3.7） |
| `/api/versions?dim=&cx0=&cz0=&cx1=&cz1=` | GET | 矩形区域内每区块的 64bit 版本号，Blender 低频轮询做增量刷新 |
| `/api/texture?block=&tint=` | GET | 方块贴图 PNG（按需染色），供 Blender 建材质缓存 |

全部响应带 `Content-Encoding`；`/api/versions` 返回紧凑二进制（cx,cz,varint 版本号）。

### 3.4 区块负载格式 MCC1（原始块数据模式）

```
magic "MCC1"                     4B
dim        varint-len + utf8
cx, cz     i32 × 2
yBottom    i16                   （如 -64）
secCount   u8                    （384/16 = 24）
presentMask u32                  bit i = 第 i 个 Section 非空
── 每个 present Section（自低向高）──
paletteSize u16
  palette × N:  class u8 + (varint-len + utf8) 完整 BlockState 串
               如 "minecraft:oak_stairs[facing=north,half=bottom]"
bitsPerIndex u8
packedIdx   ceil(4096 × bits / 8) 字节，LSB 优先（对齐 MC 自身格式）
── 整体 zstd 压缩 ──
```

典型地表区块压缩后 **2–15 KB**，localhost 传输耗时忽略不计。

### 3.5 方块分类（class 字节）

模组侧利用官方遮挡判定接口（如 `canOcclude()`、`skipRendering(邻居, 朝向)` 一类）对调色板内每个 BlockState 预分类，Blender 拿到即用、零成本：

| class | 含义 | 典型 | 剔除行为 |
|---|---|---|---|
| 0 | 空气 | air | 不产生面 |
| 1 | 不透明全方块 | stone, dirt | 邻居可完全遮挡时剔除 |
| 2 | 自剔除透明 | glass, ice | 同类相邻剔除内部面；对不透明块不构成遮挡 |
| 3 | 液体 | water, lava | 液-液剔除；仅上表面+临空侧面生成；v1 统一满格高度 |
| 4 | 镂空不剔除 | 树叶(fancy)、花草、栅栏栏板 | 不剔也不遮挡（提供"树叶快速模式"开关：按 class1 处理） |
| 5 | 非立方体 | 楼梯、台阶、门、围栏 | 见 §5.5 策略 |

### 3.6 区块版本号

mixin 拦截 `LevelChunk#setBlockState`（及同类注入点），命中时对该区块的 64bit 计数器 +1。Blender 侧在**相机静止或低频轮询**时调 `/api/versions`，版本变化的区块重新入队——游戏内边改边预览成为可能。

### 3.7 成品网格格式 MCM1（模式 B，推荐）

模组内直接做剔除 + 贪心合并 + AO（见 §5），输出 quad 流：

```
magic "MCM1"                     4B
dim / cx / cz / yBottom           同 MCC1
palette                           同 MCC1（Blender 据此建材质）
quadCount u32
── 每个 quad（约 34B）──
positions  4 × 3 × i16            相对区块原点的整型块坐标（贪心合并不产生亚格顶点）
dir        u8                     0..5 六向
blockId    u16                    palette 索引
ao         4 × u8                 顶点 AO（0..3），可关闭
tintFlag u8 + 3B rgb              群系染色（草/叶/水），无则 0
uv 不传输                          由 dir + 顶点坐标按 §5.4 规则推导
```

约 2k quads/区块 → **~70 KB**，localhost 无压力。

> **注意**：方块"精确模型"（楼梯/围栏的真实形状）来自资源包，属于客户端资产——独立服务端没有。因此 v1 服务端模式对 class5 只做全方块近似；精确模型四边形烘焙需要单人（客户端）模式支持，放 M3（§5.5、§8）。

### 3.8 贴图服务

- `/api/texture?block=minecraft:grass_block_top&tint=<rgb>`：从资源包提取贴图，可带染色；
- Blender 首次遇到某 blockId 时拉取并缓存为材质，之后全程复用；
- 动画方块（水、岩浆、原木截面朝向）v1 用静态贴图 + 默认朝向，v2 再增强。

## 4. Blender 侧：桥接插件

### 4.1 结构

```
mc_bridge/
  __init__.py   注册/反注册（properties, panels, operators, handlers, timers）
  props.py      场景级属性组
  ui.py         N 面板（连接、半径、Y 范围、预算、LOD、状态灯）
  net.py        HTTP 客户端（urllib + zstandard，纯线程安全）
  scheduler.py  调度/生命周期/版本轮询
  importer.py   快速建 mesh / 删除与清理
  mesher.py     （模式A备用）numpy 贪心网格器
  mats.py       材质缓存 / 顶点色着色节点
  ops.py        连接 · 立即刷新 · 全部卸载 · 区域烘焙 · 渲染预热
```

### 4.2 面板参数（默认值）

| 参数 | 默认 | 说明 |
|---|---|---|
| host / port | 127.0.0.1 / 8788 | MC 模组服务地址 |
| 跟随目标 | 当前场景相机 | 可指定任意 object 作为锚点 |
| R_load | 10 区块（160 格） | 加载半径 |
| R_unload | R_load + 4 | 卸载半径（迟滞，防抖动，见 §4.3） |
| y_min / y_max | -64 / 320 | 按镜头活动高度裁剪可大幅省内存 |
| inflight | 4 | 并发请求上限 |
| apply_per_tick | 2 | 主线程每次应用网格数上限（防视口卡顿） |
| debounce | 移动 ≥8 格 或 ≥20 帧 | 相机抖动抑制，避免重算需求集 |
| retry | 3 次 · 0.5s 指数退避 | 失败重试 |
| versions_poll | 5s（仅相机静止时） | 增量刷新 |
| LOD 距离 | 0–40 近 / 40–96 中 / 96+ 远 | 见 §5.6 |

### 4.3 调度器逻辑

```
tick（bpy.app.timers 0.25s 或 frame_change 触发）:
  p = 锚点世界坐标; 若移动 < 8格 且未到冷却 → 返回
  center = 世界坐标 → 区块坐标
  need   = 圆盘(center, R_load) ∩ Y范围
  missing = need − live − inflight
      → 按 距 center 的距离 排序入优先队列（近者先加载，远处自动延后）
  evict  = live − 圆盘(center, R_unload)          ← 卸载半径 > 加载半径 = 迟滞
      → EVICTING：删 object + 删 mesh 数据块；每 50 次卸载做一次 orphans_purge

worker 线程: 出队 → GET /chunk 或 /mesh → 解码（模式A在此网格化）→ ready队列
主线程 timers 回调: 每次最多应用 apply_per_tick 个 ready → 创建 object → LIVE
```

**生命周期状态机**：

```
UNLOADED ─入加载半径─► QUEUED ─► FETCHING ─► READY ─主线程应用─► LIVE
   ▲   (失败: RETRY ≤3, 指数退避)                    │
   └──────── 出卸载半径 → 删除 object + mesh ◄───────┘
```

关键点：

- **迟滞半径**是内存平衡的核心：加载半径内保证"看到即有"，多出的 4 区块缓冲带让来回晃动的相机不会反复装卸同一批区块；
- **按需取数**：只请求 missing，且近处优先；相机快速掠过时远处请求自动被更高优先级插队/淘汰；
- **分帧应用**：建 mesh 只在主线程做（Blender API 限制），每次最多 2 个区块，视口保持流畅；
- **版本增量**：静止期轮询 `/api/versions`，只有版本变化的区块重新拉取。

### 4.4 线程模型

| 线程 | 工作 | 依据 |
|---|---|---|
| worker × N | HTTP 请求、zstd 解压、（模式A）numpy 网格化 | socket/zstd/numpy 均释放 GIL，多线程有效 |
| 主线程 | 一切 `bpy.data`/对象操作，通过 `bpy.app.timers` 回调执行 | Blender 数据 API 仅主线程安全 |

### 4.5 快速建 mesh

- 顶点为整型块坐标 → 转 f32 后 `foreach_set` 一次写入 vertices / loops / polygons（不同 Blender 版本属性名略有差异，封装一层适配）；
- `use_smooth = False`（flat 着色即 MC 观感，无需自定义法线）；
- UV 层：`uv_layers.new()` + `foreach_set("uv", ...)`；
- 顶点色层：`color_attributes.new("Col", type='BYTE_COLOR', domain='CORNER')`，rgb = 群系染色、a = AO；
- MVP 阶段可先 `from_pydata`，验证后换 foreach_set（快 5–10 倍）。

### 4.6 对象管理与回收

- 所有动态对象放入集合 `MC Dynamic`，object 上写 `mcx_key = "dim:cx:cz"`、`mcx_state`、`mcx_version`；
- 卸载 = 删 object + `bpy.data.meshes.remove(mesh)`，并周期性 `bpy.data.orphans_purge()`；
- 打开含残留动态对象的 .blend 时（load_post）弹窗选择：**转为静态保留** 或 **全部清除**；
- save_pre 提示：动态对象虽可随 .blend 保存，但建议先"烘焙静态化"（§6.3）再存档交付。

### 4.7 材质系统

- 每个首次出现的 blockId 建一个材质：Image Texture（`/api/texture` 拉取，extension=**Repeat**）→ Principled BSDF（roughness 1.0，specular 0）；
- **块单位 UV**：面 UV 直接使用世界块坐标（如 ±Y 面用 (x, z)，±X 面用 (z, y)，±Z 面用 (x, y)），贪心合并出的大四边形天然获得 0..w、0..h 的连续 UV，配合 Repeat 平铺完全正确——这是贪心合并与贴图正确性共存的关键；
- 顶点色 `Col` 与贴图相乘：rgb 提供草/叶/水群系染色，a 提供 AO；
- 水材质：alpha ≈ 0.8，v2 加 UV 滚动动画；
- 材质全局缓存，跨区块复用；数百个 16×16 小贴图对显存无压力。

### 4.8 Blender 处理器挂点

| 挂点 | 用途 |
|---|---|
| `bpy.app.timers`（0.25s） | 相机轮询 + ready 队列分帧应用（不依赖播放状态） |
| `frame_change_post` | 播放/拖动时间线时立即触发一次调度检查 |
| `depsgraph_update_post` | （防抖）锚点被移动时触发 |
| `load_post` | 检测残留动态对象，提示转静态或清除 |
| `save_pre` | 提示烘焙/静态化建议 |
| `render_init` / `render_end` / `render_cancel` | 触发渲染预热（§6.3），结束后恢复跟随 |

## 5. 减面算法

### 5.1 面剔除规则（基于 §3.5 的 class 矩阵）

| 当前方块 \ 邻居 | 0 空气 | 1 不透明 | 2 透明 | 3 液体 | 4 镂空 | 5 非立方体 |
|---|---|---|---|---|---|---|
| 1 不透明 | 生成 | 剔除 | 生成 | 生成 | 生成 | 生成 |
| 2 透明 | 生成 | 生成 | **同类剔除** | 生成 | 生成 | 生成 |
| 3 液体 | 生成 | 剔除 | 生成 | **同类剔除** | 生成 | 生成 |
| 4 镂空 | 生成 | 生成 | 生成 | 生成 | 生成（快速模式除外） | 生成 |

补充：液体只生成上表面（上方非液体时）与临空侧面；跨区块边界的剔除由模组直接查世界邻居，无接缝问题。

### 5.2 顶点 AO

对每个面的 4 个角计算经典 AO（side1 / side2 / corner 占据数 → 0..3），写入顶点色 alpha。要点：

- 面被剔除的判断只看**面方向邻居**，AO 计算额外看面法线方向的 3×3 邻域；
- AO 是贪心合并的**合并约束之一**（§5.3），保证大四边形着色不穿帮。

### 5.3 贪心合并（Greedy Meshing）

逐 Section、逐轴向扫平面，经典 Lysenko 算法：

```
for d in (X, Y, Z):
  (u, v) = 其余两轴
  for slice in 沿 d 的每一层:
    mask = [None] * 16 × 16
    for cell(u, v):
      a, b = 本层方块, 沿 d 的邻居
      fa = visible(a→b, +d); fb = visible(b→a, −d)     # §5.1 矩阵
      mask[u,v] = key(a, +d, ao_sig_a) 或 key(b, −d, ao_sig_b) 或 None

    # key = (dir, blockId, tint, ao_sig)  ← 四元组完全相同才可合并
    扫描未使用格 → 沿 u 扩宽 w → 沿 v 扩高 h（整行 key 相同）
    emit_quad(d, slice, u, v, w, h, key); 标记 used
```

- **合并约束**：朝向、方块 id、染色、AO 签名（4 角打包 u16）必须一致——近景保持视觉正确；
- **远景 LOD 可放开 AO 约束**进一步减面（§5.6）；
- 合并范围 v1 为单区块内（跨区块合并收益 <2%，不做）；
- 实测经验：相对逐面输出，**地表区块减面 60–90%，纯地形可达 95%**；
- 复杂度 O(3 × 24 × 256 × 扩展)，Java 侧单区块 5–20ms。

### 5.4 UV 与纹理平铺（关键设计）

贪心合并产生覆盖 w×h 格的大四边形，纹理必须平铺：

- UV 用**世界块坐标**（§4.7），贴图 Image Texture 节点设 **Repeat**——平铺天然正确；
- 不采用图集：图集内子矩形无法用 uv>1 的 Repeat 平铺，强行做只能把大四边形按格拆碎，等于放弃合并收益。**每方块独立材质是正确性与减面兼得的最低成本解**。

### 5.5 非立方体方块（class 5）

| 阶段 | 策略 |
|---|---|
| v1（服务端模式） | 全方块近似（材质取该方块侧面贴图），输出时标记 `approx=1`；楼梯/台阶观感误差小，围栏/玻璃板误差大 |
| 缓解手段 | 插件提供"特殊方块清单"：对镜头敏感区域，可对这些坐标用 Blender 手工模型替换（导出时给出清单） |
| v2（单人/客户端模式） | 在客户端烘焙官方方块模型四边形（模型 quads + 朝向 + tint）按 class5 坐标打包下发，与全方块 quad 流合并 |

### 5.6 LOD 三档

| 档 | 距离 | 生成方式 | 视口/渲染 |
|---|---|---|---|
| LOD0 近 | ≤40 格 | 完整剔除 + 贪心合并 + AO | 始终显示 |
| LOD1 中 | 40–96 格 | 合并放开 AO 约束，过滤 <1 格碎片面 | 始终显示 |
| LOD2 远 | >96 格 | 仅生成 WORLD_SURFACE 高度壳（顶面 + 侧裙） | 默认仅视口显示，渲染可关 |

LOD 升降级 = 卸载重建该区块（版本号不变则直接换 mesh），切换发生在相机移动过程中，远档区域小面片本就不显眼。

## 6. 动态加载与内存平衡

### 6.1 内存平衡手段汇总

1. 加载/卸载**双半径迟滞**（R_load=10 / R_unload=14）；
2. 空 Section 不产生任何几何；Y 范围按镜头活动高度裁剪（如 -20..120）；
3. LRU + 立即删除 object 与 mesh 数据块 + 周期 `orphans_purge`；
4. inflight / apply_per_tick 双预算防尖峰；
5. 软上限 `max_live_tris`（默认 2M）：超限自动缩 R_load 或提升 LOD 比例；
6. 远景 LOD2 高度壳几乎零开销。

### 6.2 内存预算（经验估算，受地形与 Y 范围影响大）

| 档位 | R_load | 活动区块数 | 估算 quads（1.5k/区块） | 三角形 | Blender 峰值内存（估） |
|---|---|---|---|---|---|
| 近景特写 | 6 | ~137 | ~20 万 | ~40 万 | < 300 MB |
| 标准 | 10 | ~347 | ~52 万 | ~100 万 | ~500 MB |
| 大场面 | 14 | ~633 | ~95 万 | ~190 万 | ~900 MB |

空中/海洋区块远低于此值；配合 Y 裁剪可再降 50%+。

### 6.3 渲染工作流（确定性保证）

| 模式 | 流程 | 适用 |
|---|---|---|
| **A. 渲染预热**（默认） | `render_init` → 遍历渲染帧范围逐帧评估相机位置 → 求并集 need → 同步批量拉取（带进度条）→ **冻结跟随** → 渲染 → `render_end` 恢复 | 本机渲染；渲染中零网络依赖、零帧间装卸 |
| **B. 烘焙静态化** | 操作符把当前 need（或手选包围盒）导出为 .blend 库（每区块一个 object），场景链接引用 | 交付渲染农场（农场无 MC 环境）、长期项目资产化 |
| C. 直连渲染（不推荐） | 渲染中逐帧拉取 | 仅实验；帧间装卸风险高 |

### 6.4 与游戏内改动的协同

游戏中边改边预览：相机静止时 5s 轮询 `/api/versions` → 变化区块重新入队 → 分帧替换 mesh。渲染预热时强制做一次全量版本核对，保证渲染内容与地图当前状态一致。

## 9. 风险与备选路线

| 风险 | 缓解 |
|---|---|
| MC 内部 API 随版本漂移 | 锁定目标版本 + 模组内做薄适配层（API 面窄：Section 调色板、遮挡判定、贴图提取） |
| 单人游戏 ESC 暂停冻结集成服务端 | 使用独立服务端，或"对局域网开放" |
| Python GIL 限制 Blender 侧算力 | 默认模式 B（Java 侧网格化）；模式 A 用 numpy 向量化，仍不足则仅作调试 |
| class5 全方块近似穿帮 | 特殊方块清单 + 手工替换；或启用 v2 客户端模型烘焙 |
| 材质数量多导致 draw call 偏高 | 每区块几何已合并，材质数 = 出现过的方块种数（典型 <200），EEVEE 可承受；必要时按方块共享材质（同贴图不同 id 合并） |
| 大范围最终渲染超内存 | max_live_tris 软上限 + 烘焙静态化分流 |

**备选实现路线**（不依赖自研模组时）：

1. **Carpet 模组 + scarpet 脚本**：scarpet 提供方块查询与文件写出能力，可写一个"区块导出脚本"，零 Java 开发；缺点是吞吐低、依赖 Carpet 版本，仅适合小范围验证。
2. **RCON + 读存档**：`save-all flush` 后直接解析 region 文件（可参考 Amulet 类库思路）；无需模组，但要自己跟随存档格式，且每次都要 flush，一致性体验差。
3. **现成工具定位对照**：Mineways / jMC2Obj = 静态导出（本方案取代其动态性）；Chunky = 参考其区块网格化实现；Distant Horizons = 游戏内 LOD（思路同源、场景不同）；MCprep = Blender 侧材质/资产（可与之互补）。
